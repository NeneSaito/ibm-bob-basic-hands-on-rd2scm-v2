## 実装手順

1. `faq-data.js` を作成する。
   * `var FAQ_DATA = [...]` として定義する(`file://` で動作させるため ES Modules は使わない)。
   * 各項目は `{ id, category, question, answer }`。`id` は `qa.md` の順に `1` から `17` を振る。
   * `category` は「全般」「使い方」「高度な機能」「トラブルシューティング」。
   * `answer` はブロックの配列とする。ブロックは `{ type: "p", text }` または `{ type: "ul", items: [text, ...] }`。
   * `text` 内の `` `コード` `` と `**強調**` は記号で表現し、`app.js` が DOM 要素に変換する。
   * コード表記・固有名詞(`@/src/file.ts`、`@problems`、`.bob/rules/`、`MCP`、`Bob`、`Ctrl/Cmd + Z` など)は原文のまま維持する。
   * 訳語を統一する(例: auto-approval は「自動承認」、checkpoints は「チェックポイント」)。
2. `index.html` を作成する。
   * `lang="ja"`、viewport meta、`<title>`、`style.css` の読み込み。
   * `<header>`、`<main>`(検索 `<input type="search">` とその `<label>`、カテゴリボタン群、件数表示 `aria-live="polite"`、FAQ一覧コンテナ、空状態要素)、`<footer>`。
   * スクリプトは `faq-data.js`、`app.js` の順に `</body>` 直前で読み込む。
3. `style.css` を作成する。
   * 配色は白背景・濃いグレー文字・青系アクセントで、コントラストはWCAG AA相当を目安にする。
   * 本文幅は最大720px程度で中央寄せ。スマートフォン幅ではカテゴリボタンを折り返す。
   * `:focus-visible` で明確なフォーカス表示。選択中のカテゴリボタンは色で区別し、`aria-pressed` に連動させる。
   * 外部フォント・外部画像は使わない。
4. `app.js` を作成する。
   * 状態: `selectedCategory`(初期値「すべて」)、`query`(初期値空)。
   * 初回描画: `FAQ_DATA` の全項目をDOM生成する。質問は `<h2>` 内の `<button aria-expanded aria-controls>`、回答は `id` を持つ `<div role="region">` として生成し、初期状態は閉じる。
   * 本文の描画は `createElement` と `textContent` のみを使う。`innerHTML` は使わない。`` ` `` と `**` は小さな関数で `<code>` と `<strong>` に変換する。
   * 絞り込み: カテゴリ一致 AND 質問・回答の検索対象文字列に `query` が部分一致(大文字小文字無視、前後の空白除去、`String.prototype.includes` を使い正規表現にはしない)。
   * 検索対象文字列は、記号(`` ` `` と `**`)を除いたプレーンテキストを項目ごとに事前計算する。
   * 絞り込み結果は各項目の `hidden` 属性で切り替える(開閉状態を維持する)。
   * 件数表示を「N件」に更新し、0件のときは空状態要素「該当する質問が見つかりませんでした」を表示する。
   * イベント: 検索 `input`、カテゴリボタン `click`、質問ボタン `click`(Enter/Space はボタンの標準動作)。
5. ブラウザで `index.html` を開いて動作を確認し、問題があれば修正する(検証計画参照)。

## GUI実装

* 対象コンポーネント: 単一画面 `index.html`。ヘッダー、検索ボックス、カテゴリボタン群、件数表示、FAQ一覧(アコーディオン項目)、空状態メッセージ、フッター。
* スタイル: `style.css` に集約。クラス名は用途ベースの単純な命名とする。
* 状態管理: `app.js` 内の変数 `selectedCategory`、`query` と、各項目のDOM(`aria-expanded`、`hidden`)で管理する。外部状態管理は使わない。
* 画面遷移: なし。
* レスポンシブ対応: 最大幅付きの1カラム。スマートフォン幅(約360px以上)で横スクロールなし。カテゴリボタンは折り返し。タップしやすい高さ(約44px以上)を確保する。

### 実装手順(追加改修)

1. `index.html` を修正する。
   * `<header>` 内に `.header-inner`(左右に配置するコンテナ)を作る。
   * 左側: `<a class="logo-link" href="https://www.ibm.com/products/bob" target="_blank" rel="noopener noreferrer">` の中に `<img src="bob.svg" alt="Bob(IBM Bob 製品ページへ)" height="40">`、続けて既存の `<h1>`。
   * 右側: `<button id="theme-toggle" type="button" aria-pressed="false">ダークテーマ</button>`。
2. `style.css` を修正する。
   * `:root` の変数をライト配色にする: `--page: #f4f4f4`(ページ背景)、`--bg: #ffffff`(カード等)、`--surface: #f4f4f4`、`--border: #e0e0e0`、`--text: #262626`、`--muted: #525252`、`--accent: #2563eb`、`--accent-text: #ffffff`、`--header-start: #0f62fe`、`--header-end: #8a3ffc`、`--badge-bg: #e8eefc`、`--badge-text: #1d4ed8`。
   * ダーク配色を `:root[data-theme="dark"]` に定義する: `--page: #262626`、`--bg: #333333`、`--surface: #3d3d3d`、`--border: #525252`、`--text: #f4f4f4`、`--muted: #c6c6c6`、`--accent: #78a9ff`、`--accent-text: #161616`、`--header-start: #0043ce`、`--header-end: #6929c4`、`--badge-bg: #1f3a6e`、`--badge-text: #a6c8ff`。
   * (2026-10-24T17:01:38+09:00 変更: 配色をモックに合わせて見直した。`--decor` は廃止し、ヘッダー背景用の `--header-start` / `--header-end`、ページ背景 `--page`、バッジ用の変数を追加した。変更ファイルは `style.css` のみ。)
   * `@media (prefers-color-scheme: dark)` 内で `:root:not([data-theme="light"])` に同じダーク変数を定義する。これにより、保存設定がなければJavaScript実行前からOS設定に従う。
   * `.site-header` の背景を `linear-gradient(135deg, var(--header-start), var(--header-end))`、文字を白にする(下線は廃止)。切り替えボタンはヘッダー上で読める白系(半透明の暗い背景+白文字、押下時は白背景+暗い文字)とし、`.faq-category` は `--badge-bg` / `--badge-text` のバッジにする。`.header-inner` を `display: flex; align-items: center; justify-content: space-between; flex-wrap: wrap; gap` とし、最大幅720px・中央寄せにする。`h1` の余白は `.header-inner` 側で調整する。
   * `.logo-link` は `display: flex; align-items: center; gap` でロゴとタイトルを並べる。ロゴは高さ約40px。
   * `#theme-toggle` は既存のカテゴリボタンに近い見た目とし、`aria-pressed="true"` のとき白背景+暗い文字で区別する。高さ44px以上。
   * 既存のハードコード色は変数に置き換える(`style.css` の `#f0a000` のフォーカス色は両テーマで十分なコントラストがあるため維持する)。
3. `app.js` を修正する。
   * 既存の即時関数内に、テーマ処理を追加する。
   * 初期化: `localStorage` の `bob-faq-theme`(`"light"` または `"dark"`)を読む。値が有効ならそれを使い、なければ `matchMedia("(prefers-color-scheme: dark)").matches` で判定する。
   * 適用: `document.documentElement.setAttribute("data-theme", theme)` と、切り替えボタンの `aria-pressed` を更新する。
   * 切り替え: ボタン押下でテーマを反転し、適用して `localStorage` に保存する。
   * `localStorage` の読み書きは `try/catch` で囲み、失敗時は保存せずに動作を継続する(エラーは握りつぶしてよい。ユーザー入力ではなく環境要因のため)。
   * 保存値は `"light"` / `"dark"` の許可リストで検証し、それ以外は無視する。
4. 構文確認とブラウザでの手動確認を行う(検証計画参照)。ダークでのロゴ視認性を確認し、結果をユーザーに報告して対応要否の判断を仰ぐ。
